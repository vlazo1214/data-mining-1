  1. Subset selection paths
predict_regsubsets <- function(object, newdata, id, formula) {
  mat <- model.matrix(formula, newdata)
  coefi <- coef(object, id = id)
  # Ensure column alignment
  pred <- mat[, names(coefi), drop = FALSE] %*% coefi
  as.numeric(pred)
}

kfold_cv_regsubsets <- function(data, formula, nvmax, method = "exhaustive", K = 10, seed = 1) {
  set.seed(seed)
  n <- nrow(data)
  folds <- sample(rep(1:K, length.out = n))
  cv_err <- matrix(NA_real_, nrow = K, ncol = nvmax)

  for (k in 1:K) {
    tr <- data[folds != k, , drop = FALSE]
    va <- data[folds == k, , drop = FALSE]

    fit <- regsubsets(formula, data = tr, nvmax = nvmax, method = method)

    for (s in 1:nvmax) {
      pred <- predict_regsubsets(fit, va, id = s, formula = formula)
      y_va <- model.response(model.frame(formula, data = va))
      cv_err[k, s] <- mean((y_va - pred)^2)
    }
  }
  colMeans(cv_err)
}

Problem 4: Short answers

  1. Training error is the metric that shows model performance when it is initially trained on the training data whereas testing error is used to measure model performance on new data (testing data). Training error should not be used to estimate generalization performance because it is not representative of the entire dataset, it has only been trained on a portion and has not had a final evaluation.

  2. One example of data leakage caused by preprocessing is in a time-series dataset, random shuffling is used. The data’s order needs to be preserved because if points from the future end up in the training set, it could cause the model to seemingly perform well but is not actually representative of the data. The way to correct this is sorting the data by an appropriate metric before any splitting occurs to preserve the order.

  3. Using CV as a final model performance is not correct because there needs to be a final pass of the testing set. The last step of running the testing set through the model is crucial because it captures true model performance by seeing how well the model does to unseen data (testing set) from the original (training) dataset. The testing process is a simulation of giving the model real-world data that is relevant because it came from the same dataset. One remedy is splitting the data into training/validation/testing. The model is first trained on the training data to serve as a baseline. The tuning of hyperparameters occurs during the validation process. The testing set is used to give a final evaluation of the model after training and validation occurs.

  4. One metric that emphasizes ranking quality is the AUC and one metric that emphasizes decision quality at a specific threshold is the F1 score.
